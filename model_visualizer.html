TRANSLATION NORMALIZATION
The "Top-Left" Origin Problem & Wrist Anchor

Webcam screens place (0,0) at the top-left corner. If you make a thumbs-up on the left of your webcam vs the right, raw numbers are completely different:

# Left of screen: Wrist=(0.20, 0.30), Thumb=(0.20, 0.15)
# Right of screen: Wrist=(0.80, 0.70), Thumb=(0.80, 0.55)
→ Model overfits to WHERE you sit, not hand shape!

# Solution: Anchor to Wrist (P_rel = P_raw - Wrist):
Left: (0.20-0.20, 0.15-0.30) = [0.0, -0.15]
Right: (0.80-0.80, 0.55-0.70) = [0.0, -0.15]
✓ 100% Identical anywhere on screen (Translation Invariant)
Interview Takeaway: Subtracting the wrist coordinate transforms the hand into its own local coordinate system where Wrist = $(0,0,0)$. The neural network becomes blind to screen position and focuses purely on joint geometry.
DEPTH & SCALE NORMALIZATION
Why Translation Fails for Z-Depth & How Scale Fixes It

Translation normalization ($P - Wrist$) shifts the origin, but does not fix perspective foreshortening or camera distance. As you lean in, $X, Y, Z$ spans expand; as you lean back, they shrink.

# The Normalizing Scalar:
d_i = sqrt(x_i^2 + y_i^2 + z_i^2) # 3D Euclidean distance
max_dist = max(d_i) # Max radius to furthest point

# Divide all 21 (x, y, z) coordinates by max_dist:
relative /= max_dist
→ Furthest point (Middle Finger Tip #12) = 1.0
→ All 21 landmarks lie within unit sphere R ≤ 1.0
What is the Scalar? The scalar is max_dist: the maximum 3D Euclidean straight-line distance from the wrist to the furthest landmark on that hand. Dividing $X, Y,$ and $Z$ by this single scalar preserves true 3D hand proportions while making depth and distance scale-invariant.
TECHNICAL NUANCE
"Removed" vs "Zero-Centered" Landmark 0

Casual documentation often says "we removed the wrist landmark". A technical interviewer will ask: "Why are there 63 features per hand instead of 60?"

21 landmarks × 3 coords (x,y,z) = 63 values per hand
Landmark 0 (Wrist) = [0.0, 0.0, 0.0]
Landmarks 1-20 (Fingers) = Relative vector offsets
Interview Answer: "The wrist was anchor-zeroed, not deleted. Retaining Landmark 0 as $[0,0,0]$ preserves standard MediaPipe 21-landmark indexing while completely stripping out global coordinate bias."
ARCHITECTURE & SKEPTIC VIEW
Was 126D Flattening the Right Choice?

We flatten Left Hand (63) + Right Hand (63) into a single 126D vector per frame across 30 time steps.

✓ Why it was right: Seamlessly handles 1-handed signs (absent hand slots are all zeros) and 2-handed signs without needing two model branches. 60+ FPS on CPU.

⚠ The Trade-Off: Because each hand is normalized to its own wrist, the model loses the exact physical distance between both hands.

Pro Proposal for Interview: "For complex signs where hand proximity matters (e.g. palms touching vs apart), we can append a 3D inter-wrist vector $\vec{V}_{inter} = \vec{P}_{right} - \vec{P}_{left}$ ($126 + 3 = 129\text{D}$) to explicitly preserve inter-hand distance."

Long Short-Term Memory (LSTM) Cell Anatomy

How each neuron inside our 3 LSTM layers remembers, updates, and forgets hand gesture history over 30 time steps.

Memory Cell State: Cₜ | Hidden State: hₜ
1. FORGET GATE

What to discard?

fₜ = σ(W_f · [hₜ₋₁, xₜ] + b_f)

Decides what percentage of old hand positions to forget (e.g. discarding rest position once a gesture begins). Output is between 0 and 1.

2. INPUT GATE

What to update?

iₜ = σ(W_i · [hₜ₋₁, xₜ] + b_i)

Filters which incoming landmark changes in frame t are significant enough to write into the memory belt.

3. CANDIDATE CELL

New information candidate

C̃ₜ = tanh(W_c · [hₜ₋₁, xₜ] + b_c)

Computes a vector of new candidate values ranging between -1 and +1 to be added to the cell state.

4. CELL UPDATE & OUTPUT

Emitting current gesture

Cₜ = fₜ * Cₜ₋₁ + iₜ * C̃ₜ
hₜ = σ(W_o · [hₜ₋₁, xₜ] + b_o) * tanh(Cₜ)

Updates the long-term memory belt $C_t$ and produces the hidden state vector $h_t$ passed to the next frame or higher layer.
